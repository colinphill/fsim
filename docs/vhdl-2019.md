# VHDL-2019 support

fsim v3 accepts VHDL-2019 as a native language profile. Select it with either
`19` or `2019` in a project source set or on the command line:

```toml
[[sources]]
language = "vhdl"
standard = "2019"
library = "work"
files = ["rtl/design.vhd"]
```

```text
fsim compile --lang vhdl --standard 2019 --library work \
  --output work.fsimobj rtl/design.vhd
```

VHDL-2019 is intentionally distinct from every retained older profile.
Artifacts, elaborated designs, checkpoints, and native-cache entries record
the selected standard and its predefined-package provenance. A VHDL-2019
construct is rejected under an older profile rather than enabled as an
implicit extension.

## Language additions

The VHDL-2019 frontend and semantic model include the following supported
families:

- revised lexical rules and conditional analysis;
- protected-type revisions and dynamically allocated object lifetime rules;
- unspecified interface types with bounded contextual inference;
- the required portable predefined `INTEGER` range;
- interface view declarations, nested record views, view ports, and view
  associations;
- contextually typed conditional expressions;
- result-array constraints visible in subprogram bodies;
- sequential block statements with nested declarative regions;
- the added predefined attributes; and
- revised overload, visibility, and conformance behavior.

Objects and ports retain concrete type, range, direction, source, and standard
metadata through elaboration. Nested view connections become explicit
directional endpoints; view-based signal and variable updates enforce those
directions at their write boundaries.

## Runtime and predefined APIs

The runtime executes sequential blocks across waits and callable boundaries,
reclaims automatic access objects at deterministic safe points, and retains
observable state under the interpreter, Debug engine, and compiled LLVM O0-O3
engines.

The governed 2019 predefined environment supplies the supported simulator,
data, time, directory, environment, source-location, PSL, report/assert, and
reflection operations. File-system operations are bounded and return portable
status values. Source-location results use normalized producer metadata rather
than host addresses. Reflection values are owned typed records; they do not
expose transient simulator storage.

The `ieee` package revision and every package dependency participate in object,
design, checkpoint, and native-cache identity. A changed or unavailable
dependency is diagnosed before execution.

## Coverage

Code coverage includes executable statements in VHDL-2019 sequential blocks,
their recursively nested block-local functions and procedures, and ordinary
nested statement forests. Point IDs derive from the language, construct kind,
physical source span, and canonical source identity, so relocating an
unchanged checkout does not renumber them.

The standardized PSL controls use the existing deterministic PSL runtime.
`.fsimcov` PSL bins bind to authenticated source identities rather than
transient semantic source numbers. Renumbering internal spans therefore does
not change a bin identity; changing the bound source content does.

## VHPI

The append-only v3 VHPI host retains the complete v1 and v2 prefixes and adds
checked capability queries, typed value access, and bounded tool execution.
The information model exposes VHDL-2019 object kinds, parent/child
relationships, source coordinates, interface-view elements, standard-library
identity, and package provenance without renumbering retained identities.

Plug-ins must validate the advertised host size, ABI version, capabilities,
and required callbacks before use. Handles are generation-qualified and become
stale after their owning object is released. Tool actions and callbacks copy
bounded request data into simulation-owned storage.

## Artifacts and mixed-language designs

VHDL-2019 source can be compiled to a v3 `.fsimobj` and elaborated into a
standalone v3 `.fsimdesign`. The consumer does not require producer source or
object trees. Relocation preserves canonical source and specialization
identities, while corruption, incompatible schemas, or stale package
provenance reject transactionally.

Mixed designs may bind VHDL-2019 instances to SystemVerilog and native SystemC
instances. Scalar and arbitrary-width logic values cross those boundaries
through the common typed conversion model. Interpreter, Debug, LLVM O0/O2,
cold/warm native-cache, checkpoint, debugger, and waveform observations share
the same elaborated design semantics.

## Deliberate boundaries

- VHDL-AMS is outside the digital VHDL-2019 profile.
- Vendor-only packages, pragmas, and foreign-interface extensions are not
  enabled unless separately documented as compatibility surfaces.
- Unsupported or resource-exceeding constructs fail with a diagnostic; fsim
  does not silently downgrade them to VHDL-2008 behavior.
- v3 persisted artifacts and native plug-ins do not have v2 compatibility
  readers or migrations.
