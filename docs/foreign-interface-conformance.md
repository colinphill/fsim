# Foreign-interface conformance

This inventory lists the normative items of the SystemVerilog VPI (IEEE 1800-2023
clauses 36–38, Annex K) and of the VHPI (IEEE 1076-2019 clauses 17–23, Annex B)
and records how fsim implements each one. It drives the conformance work that
precedes first-class cocotb support; rows change status as items close.

Status values:

- **done**: implemented as the clause reads, with a test.
- **partial**: implemented with a stated gap.
- **missing**: not implemented; the routine or property raises an error.
- **N-A**: does not apply to fsim, with the reason.
- **choice**: the clause leaves the behaviour to the tool; the row states fsim's choice.

Files: `vpi` = `src/app/application_vpi_foreign.cpp`, `vpi-cb` =
`src/runtime/vpi_callback.cpp`, `vpi-val` = `src/runtime/vpi_value_control.cpp`,
`vpi-std` = `src/runtime/vpi_standard.cpp`, `vhpi` =
`src/app/application_vhpi_foreign.cpp`, `vhpi-std` = `src/runtime/vhpi_standard.cpp`,
`run` = `src/app/application_run_commands.cpp`.

## VPI callback reasons (IEEE 1800-2023 38.36)

| Reason | Status | Notes |
| --- | --- | --- |
| `cbValueChange` | done | fires in the region of the change with the captured new value; NULL value for an event; `index` set for an array word |
| `cbForce`, `cbRelease`, `cbAssign`, `cbDeassign` | done | repetitive; after the statement runs, at the next safe point, with `obj` the force, release, procedural assign or deassign statement and `value` the target's resulting value, of the bits the statement acts on (38.36.1). A NULL `obj` at registration watches every statement, a net or variable only those on it; a bit-select is refused. The processes that keep a forced or assigned value applied are not statements and make no callback (`fsim.foreign.vpi-statements`) |
| `cbStmt` | partial | vpi | only with `simulate --foreign-probes` (key `simulate.foreign_probes`); otherwise `vpi_register_cb` returns NULL and `vpi_chk_error` names the option. The run keeps the kernel's debug points, as `--engine debug` does: no cached kernel image, no multithreading. Table 38-6: a block's callback runs before its first statement; a loop's runs on entry and again before each later pass (a while or repeat loop's test, a for loop's increment). A point is matched by process, file, line and column. The event control of `always @(...)` (the `vpiEventControl` that is the process's `vpiStmt`) runs its callbacks at each activation, at the process's entry point. A statement of a generate block's process runs its callbacks: the process is named after its generate scope (`top.g[1].process_3`), whose HIR region holds the statement (`fsim.foreign.vpi-stmt`). A statement of a task or function runs its callbacks also when the caller is a process of another instance (a hierarchical call, `a.bump(1);`): registering a statement callback turns the frame model on, and the active frame of the running thread names the callee's instance (the call that activated the frame, resolved from the caller's scope, gives the task's declaring scope), so the statement point is matched in that instance and a callback placed on the statement of `top.a.bump` runs only for calls of `a`'s task (`fsim.foreign.vpi-frame-vars`, unverified). Missing: a call the lowerer inlined without a frame, from another instance, is attributed to the caller's instance: the execution point carries the callee's source position but no frame, so the owning instance cannot be told (needs the lowerer to keep the callee's scope in the inlined call's debug points, or to emit frame entry and exit for it) (`fsim.foreign.vpi-stmt`, `fsim.foreign.vpi-stmt-noprobe`) |

### PLI 1.0 association and misctf reasons (IEEE 1364-2001 21, Annex F)

21.2 leaves the association of applications with task and function names to
the vendor. A library loaded with `--vpi` that defines no bootstrap named on
the command line is read for these symbols, in this order: `vlog_startup_routines`
(run), `veriusertfs[]` (an `s_tfcell` table ended by type 0; each cell is
registered as the user task or function it describes, as
`veriusertfs_register_table` does), and `endofcompile_routines[]`. A library
needs to export only one of them. `s_tfcell` keeps the vendor table layout (`type`, `data`,
`checktf`, `sizetf`, `calltf`, `misctf`, `tfname`, `forwref`, `tfveritool`,
`tferrmessage`, `reserved`); fsim reads only the first seven fields. Test
`fsim.foreign.pli-mechanism` exports `veriusertfs[]` and
`endofcompile_routines[]` and calls no registration routine.
